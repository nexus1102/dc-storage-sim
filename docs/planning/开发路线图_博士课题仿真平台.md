# 开发路线图：从 v2 到博士课题仿真平台

**基线**：`runs/v2_20261110_085434`（120 项核验通过）
**用途**：自行开发用的施工图。每个工作包含"做什么、改哪个文件、怎么验收、依赖什么"。

---

## 0. 先定义什么叫"达到需求"

不先定义验收标准，开发会无限膨胀。我认为达到下面五条就算够用，**多做的都是浪费**：

| # | 标准 | 判定方式 |
|---|---|---|
| S1 | 能回答课题的四个核心问题 | 四个问题各有对应的输出表/图，且带区间 |
| S2 | 结论对参数稳健 | 关键参数有敏感面，不是单点结论 |
| S3 | 可复现 | 他人按 README 跑出同一组数字（哈希一致） |
| S4 | 与文献可区分 | 有对照臂，能说清"我和肇嘉毅 2026 差在哪" |
| S5 | 能支撑 ≥2 篇论文 | 运行层一篇、规划层或方法层一篇 |

**四个核心问题**：

1. 闲置容量有多大？（可调度域，而非装机减预留的一句话）
2. 它由什么决定？（冗余等级 / 穿越时间 / 业务构成，各自贡献多少）
3. 怎么调？（四类业务的差异化策略、与备用的耦合）
4. 值多少？（日运行收益、全寿命经济性、可靠性代价）

**停止规则**：当四个问题都能用"点估计 + 区间"回答，且回归基线连续三次运行无漂移，就停止加功能，转入写作。**平台是工具，不是成果本身。**

### 阶段 0：让现有结论可信（1 周）

先做这一步，因为后面所有工作都建立在现有数字上；如果现有数字不可信，返工成本会翻倍。

#### W0.1　参数溯源表 + 真实电价　`[0.5 天]`

**做什么**
1. 建 `docs/parameter_provenance.csv`，字段：`参数 / 取值 / 单位 / 来源类型(实测|文献|政策|假设) / 具体出处 / 敏感范围`。
2. 把 `PRICE` 换成省级发改委公布的分时电价（江苏或上海，注明文件号与执行日期）。
3. 把 `C_REG_CAP` 换成该省辅助服务市场规则里的容量补偿价，并补里程价（见 W1.3）。
4. 所有标为"假设"的参数，在 `uncertainty.py` 里给一个 ± 范围，纳入情景扫描。

**验收**：表中每一行都有来源类型；"假设"类参数 100% 出现在敏感面里。没有"来源：行业常见"这种模糊表述。

#### W0.2　退化成本分段线性化　`[0.5 天]`

**为什么**：`DEG_COST = 15.0` 取自你标定表的 DoD=0.9 一行，但调频是浅循环（DoD≈0.05–0.1），按你自己的标定应接近 22.5。常数 15 **系统性低估浅循环成本约 50%**，进而高估调频收益——而调频是 D 阶段最大的收益项。

**做什么**
1. 用 `results/degradation_calibration.csv` 的三档（0.3/0.6/0.9 → 22.46/21.83/14.99）构造分段线性成本，用 SOS2 变量保证档内精确。
2. 若 DoD < 0.3 无数据，用最近档外推并在文档中声明。
3. 在 `pipeline_v2.py` 里替换 `DEG_COST * DT_H * 0.5 * (p_dis + p_store).sum()`。

**验收**
- 目标函数与逐项成本对账 < 1e-2 元；
- 构造一个 DoD=0.3 的测试算例，退化成本落在 22.46±0.01 元/MWh；
- 重跑后报告调频阶段（D）的收益变化，**若变化 >10%，说明之前的结论需要修正**。

**必须写进论文的话**：以吞吐为代理、未做雨流计数，这是模型的已知边界。

#### W0.3　穿越时间敏感面　`[0.5 天]`

**做什么**：把 `T_RIDE_H` 提为配置项，跑 $$t_d\in\{3,10,15,30,45\}$$ min 五档，输出"可调度域 vs $$t_d$$"与"日收益 vs $$t_d$$"两张图。

**验收**：五档都跑通；给出"结论在哪个 $$t_d$$ 区间内改变方向"的明确表述。

**已知结果**（供你核对）：45 min 时 N 与 N+1 的可调度域归零，2N 以上闲置占比 70%–83%。

#### W0.4　2×2 因子实验 + DID　`[1 天]`

**做什么**：把 A–E 的阶梯消融改成因子设计。

- 因子 1：拓扑冗余备用（开/关）
- 因子 2：业务柔性（开/关）
- 因子 3：调频（开/关）
- 备用口径：CVaR / 固定（单因子对照）

先做 2×2（柔性 × 调频），再决定是否需要三因子全组合。

**输出**：主效应 + 交互效应，均带区间。

**验收**：交互效应 = $$B+C-A-D$$；只有下界 > 0 才写"存在正向交互"。

**为什么**：阶梯消融的边际值依赖加减顺序，无法回答"调频与柔性是否互补"。这是方法上的实质升级。

#### W0.5　认证区间　`[1 天]`

**做什么**
1. 每次求解保存 `[primal, dual]`（HiGHS 对 LP 也返回对偶界）。
2. 所有"节省""差值""交互"用区间算术计算：`diff(a,b) = (a_lo - b_hi, a_hi - b_lo)`。
3. 结论表述统一为"下界 > 0 才称显著"。

**验收**：随机抽 3 个结论，手工核对区间端点；区间端点不能出现"下界 > 上界"。

**注意**：这与 bootstrap 不冲突。bootstrap 回答"参数扰动下稳不稳"，认证区间回答"求解器没到最优时成不成立"，两者并列报告。

### 阶段 1：补齐灵活性建模（3–4 周）→ 论文一

#### W1.1　时变备用耦合　`[0.5 天]`

**做什么**：把 `pipeline_v2.py:131` 的常数 `floor` 改成依赖调度决策的时变下限：

$$\text{floor}[t]=\frac{1}{\eta_{dis}}\sum_{k=0}^{K-1}\Big[L_{base}(t+k)-p_{def}(t+k)+p_{rec}(t+k)\Big]\Delta t$$

这是**线性**约束，可直接进 linopy。

**注意**：日末窗口需要循环或截断处理；建议循环（与"当日工作当日做完"一致）。

**验收**
- 新增检查项 `reserve_floor_dynamic`，残差 < 1e-6；
- 对比修改前后：三类业务的队列峰值是否离开上限？
  - **若离开**：证明"平移有代价"确实抑制了柔性，这是一个可写进论文的结论；
  - **若未离开**：说明当前参数下备用代价不足以抑制平移，同样要报（负结果也是结果）。

#### W1.2　虚拟储能（机房热惯性）　`[1–2 周]`

**做什么**：加入一阶 ETP + 虚拟电池：

$$e_{t+1}=\alpha e_t+\beta P^{ch/dis}_t+\gamma P^{IT}_t+(1-\alpha)e_0,\quad 0\le e_t\le 1$$

$$P^{ch/dis}_t=P^{ac}_t-P^{base}_t,\quad P^{ac}_t\ge 0$$

系数**自行从热平衡推导**，不要照抄文献（PDF 提取有歧义，见上一份分析）。

**关键**：$$P^{IT}$$ 是决策相关的（受 `def`/`rec` 影响），这一步同时接上了"算 → 冷"耦合。

**验收**
- 虚拟 SOC 递推残差 < 1e-6，SOC ∈ [0,1]；
- 高价时段前应出现"预冷"（P_ac 高于基线），价格曲线与 P_ac 的互相关应为负；
- 加入后重算可调能力上限，**并重算备用需求与调频可用容量**（三者都变，不能只加不算）。

#### W1.3　里程补偿 + 调频退化　`[3 天]`

**做什么**
1. 收益加里程项：$$C^{aux}=\sum_t(e^c_t+\eta_{mil}e^{mil}_t)P^{reg}_t$$
2. 退化加调频吞吐：$$\sum_t 2\beta_t P^{reg}_t c_d$$
3. 参数（$$\eta_{mil},\ e^{mil},\ \beta$$）从该省辅助服务市场规则取值并记入溯源表。

**验收**：调频收益分解为容量费/里程费两项，比例合理（国内通常里程占比更高）；重跑消融 D 阶段。

#### W1.4　业务参数的实证与敏感性　`[3 天]`

**做什么**
1. 从 Alibaba trace 统计每类业务的实际可中断比例、可延迟时长分布，替换现在的工程假设（0.20/2h/0.30 等）。
2. 若 trace 不足以支撑，明确标为假设，并对 f、W、ρ 各做 ±50% 的敏感面。
3. 加一个**作业级可分解性检查**：给定聚合 `def/rec` 轨迹，用 L1 最小化求作业级分配；若最小 L1 超过阈值，报告"聚合平移不可分解为作业级调度"。

**验收**：每个业务参数有"实测值或假设+敏感面"；可分解性检查在 40 情景上通过率 >95%。

#### W1.5　公式—代码追溯表　`[1 天]`

**做什么**：`docs/formula_traceability.csv`，字段：`公式 / 含义 / 代码位置 / 处理类型(原样|修正|简化) / 验证检查项 / 边界说明`。

**验收**：每个核心公式都有对应检查项；每个"简化"都有边界说明。

### 阶段 2：规划层（4–6 周）→ 论文二

#### W2.1　容量配置 MILP　`[2 周]`

**做什么**：新建 `sim/sizing.py`。模块数变为整数决策变量：

$$\min\ \sum_m c^{cap}_m n_m\cdot \text{CRF}+\ 365\cdot\text{OPEX}(n,\text{调度})$$

约束沿用 `solve_case` 全部约束 + N-1 判定 + 可靠性下限。

**验收（最重要的一条）**：把 $$n$$ 限制在五个架构对应值上时，**必须复现 v2 的成本数字**（误差 <1e-3）。这是新模块正确性的强锚点。

附加检查：负荷↑ 时最优模块数不减（单调性）；gap < 1e-4。

#### W2.2　全寿命经济性　`[1 周]`

**做什么**：CAPEX（元/kWh 系统造价）、CRF、年运行成本、退化导致的更换成本，输出 NPV / 投资回收期 / LCOE 式指标。

**验收**：与"只算日运行成本"的结论对比，**若排序改变，说明规划层必要**；若不变，也是一个有价值的稳健性结论。

#### W2.3　多目标 Pareto（增广 ε-约束）　`[1 周]`

**做什么**：固定成本，扫 EENS 上限；或用增广 ε-约束抓非支撑点。输出成本—可靠性前沿。

**验收**：前沿单调（成本↑ 则 EENS↓）；与加权和法的结果对比，说明为何用 ε-约束。

**不要用 NSGA-II**：线性/MILP 模型下 ε-约束给的是精确前沿，NSGA-II 是近似。

#### W2.4　退化—寿命耦合（简化版）　`[1 周]`

**做什么**：把年度吞吐映射为容量衰减，影响可用容量与更换时点。做一版即可，不要追求雨流计数的精确实现。

**验收**：明确声明"未做雨流计数"；给出该简化对结论的影响量级估计。

### 阶段 3：决策范式（4–6 周）→ 论文三

#### W3.1　两阶段随机规划　`[1.5 周]`

**做什么**：新建 `sim/stochastic.py`，**直接用 linopy 建，不要硬掰 PyPSA**。第一阶段变量（调频投标量、备用承诺）非预见；第二阶段随场景变化。

**验收（强锚点）**：场景数 = 1 时，结果必须与确定性 LP 完全一致（误差 <1e-6）。非预见性检查：所有场景下第一阶段变量相同，残差 = 0。

#### W3.2　DRO 对照臂　`[1 周]`

**做什么**：移植模糊集最坏概率的 LP（约 40 行）。注意：给定各场景成本后，最坏概率是一个**独立的小 LP**，不需要迭代。

**验收**：最坏概率向量满足 $$\sum p=1$$ 与范数半径约束；$$\alpha$$ 增大时风险溢价单调增。

#### W3.3　统一评价器 + 范式对比　`[2 周]`

**做什么**：固定一组**样本外**情景，评价四种决策依据：确定性 / 两阶段随机 / DRO / 保守整定。报样本外成本分布、失负荷概率、违约概率。

**验收**
- 四种范式用**同一组**情景（禁止各自用最优分布）；
- 配对比较，带区间；
- 给出"哪种范式在样本外更优"的明确结论，以及它在什么条件下翻转。

**这是全文的方法贡献**：肇嘉毅 2026 及其复现代码只报样本内 4 场景，无样本外检验。

### 阶段 4：算力侧（4–6 周，可选但课题名需要）

#### W4.1　跨节点任务迁移　`[3 周]`

**做什么**：把"本地负荷平移"扩展为"多节点任务迁移"：每个节点有电价、有可用容量，任务是可迁移的。这是"算电协同"里"协同"二字的实体。

**验收**：任务总量守恒；迁移成本（带宽/时延）显式建模；与本地平移对比，量化跨节点带来的增量。

#### W4.2　MPC 滚动调度　`[3 天 – 4 周，分三级]`

"MPC"不是一种算法，是一族。先分清有哪几种，再选。

**① 变体对照**

| 变体 | 优化目标 | 不确定性处理 | 计算量 | 对你的适配性 |
|---|---|---|---|---|
| 跟踪型 MPC | 跟踪设定值 | — | 低 | ❌ 你没有设定值，经济目标是成本 |
| **经济型 MPC（EMPC）** | 直接最小化运行成本 | 确定性点预测 | 低 | ✅ 主干 |
| **机会约束 MPC（CC-MPC）** | 成本 + $$P(\text{SoC}<\text{floor})\le\varepsilon$$ | 分布已知 | 中 | ✅ 与你的 CVaR 备用同源 |
| **场景 / 多阶段随机 MPC** | 场景树上的期望成本 | 场景 + 非预见性 | 高 | ✅ 用于日前层 |
| Tube MPC | 名义轨迹 + 鲁棒不变集 | 有界扰动 | 中 | ❌ 经济目标下过于保守 |
| **分层 MPC** | 慢层定计划，快层做修正 | 分层 | 中高 | ✅ 日前—日内两级 |
| 分布式 MPC（ADMM） | 多主体分解 | 多主体 | 高 | ⏸ 仅多站点时（W4.1） |

**② 选型结论：分层经济型机会约束 MPC**

- **上层（日前）**：24 h 时域 / 1 h 分辨率，两阶段随机（第一阶段非预见），输出调频投标量与 SoC 参考轨迹。**这一层就是 W3.1，不是新东西**——MPC 只是把它放到滚动框架里。
- **下层（日内）**：4 h 时域 / 15 min 步长，机会约束 $$P(\text{SoC}_t<\text{floor}_t)\le\varepsilon$$，跟踪上层 SoC 参考，终端约束 $$\text{SoC}(T)=\text{SoC}(0)$$。
- **状态**：$$x=[\text{SoC},\ q_{train},\ q_{batch},\ q_{deliv},\ e_{ves}]$$——注意业务队列与虚拟 SOC 必须进状态，否则"日前说能做完、日内做不完"。
- **扰动**：$$w=[$$负荷预测误差$$,\ $$电价偏差$$]$$。
- **反馈**：实测 SoC + 实测负荷，每步校正。

**为什么不是别的**：跟踪型没有设定值可跟；Tube MPC 要求有界扰动，而你的不确定性是价格与负荷的分布，不是区间；纯确定性 EMPC 无法表达穿越备用，会退化成现在的静态 CVaR。

**③ 递归可行性（一定会踩的坑）**

终端等式 $$+\ \text{floor}$$ 硬约束在有扰动时会**直接不可行**。必须：
- 给 floor 约束与终端约束加松弛变量 + 大罚（软约束）；
- 记录松弛触发率，作为"计划不可执行"的度量——这本身就是一个可以写进论文的指标。

**④ 计算量警告**

$$96\ \text{步/日}\times5\ \text{架构}\times40\ \text{情景}\approx19{,}200$$ 次 LP × 3 s ≈ 16 h。**MPC 不应进主流水线**：单独脚本，只对代表性子集（如 2 架构 × 10 情景）跑，其余用开环结果。

**⑤ 价值分解实验（写论文的关键）**

三组对照，把"MPC 值多少"拆开：

| 组 | 设定 | 隔离出的价值 |
|---|---|---|
| (a) 日前开环 | 完美预测，只解一次 | 基准 |
| (b) 滚动 + 完美预测 | 每步重解，无预测误差 | $$\Delta_{reopt}=b-a$$：**重优化**价值 |
| (c) 滚动 + 真实预测 + 状态反馈 | 全 MPC | $$\Delta_{fb}=c-b$$：**反馈**价值 |

如果 $$c<b$$，说明预测误差吃掉了反馈收益，MPC 不值得做——这个负结论同样有价值，且能省下后续大量工作。

**⑥ 验收**

- 软约束触发率有记录，且给出触发时段的分布；
- 终端 SoC 闭合误差 < 1e-3；
- (a)(b)(c) 三组成本关系可解释，$$\Delta_{reopt}$$ 与 $$\Delta_{fb}$$ 分别报告（带区间）。

**⑦ 分级推进**

| 级 | 内容 | 工期 | 何时做 |
|---|---|---|---|
| MPC-0 | 确定性 EMPC 滚动（15 min 步长，4 h 时域） | 3 天 | 想验证"滚动有没有用"时 |
| MPC-1 | 加机会约束（复用 CVaR 的 ε） | 1 周 | 想与现有备用口径打通时 |
| MPC-2 | 分层（上层两阶段 + 下层跟踪） | 2 周 | 只在论文需要"实时可执行"论断时 |

**如果论文不声称实时性，这一项可以整体放弃**——它已在"加分"清单里。日前开环 + 两阶段随机已经足够支撑"投标策略"的结论；MPC 只在你需要回答"计划能不能执行、执行中偏差怎么修"时才必要。

## 5. 工程纪律（比代码更重要）

这几条决定你半年后还能不能维护这个平台。

1. **每个工作包结束时冻结基线**。`verify.py regress` 必须通过。改完不冻结，三个月后你不知道哪个数字是新的。
2. **新增约束必须配一个检查项**。没有检查项的约束，等于没有约束——v2 的两个真实 bug 都是检查项抓到的。
3. **决策日志**：`docs/decision_log.md`，每次做建模选择时记一行"选了什么 / 为什么不选另一个 / 证据在哪"。答辩时这是你的弹药。
4. **不要为了"有算法"引入启发式**。你的模型是 LP，精确算法是对的；这一点在答辩时要能讲清楚。
5. **参数改动必须走溯源表**。临时改一个常数跑通、然后忘了改回来，是最常见的隐性错误。
